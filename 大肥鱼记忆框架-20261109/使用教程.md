# 使用教程

> 从零开始，把这个记忆框架接到你自己的 AI 同伴身上。
> 全程大约 30 分钟，其中 20 分钟花在「接宿主」那一步。

---

## 零、先看清它是什么

这不是一个「装好就自动有记忆」的库。它是一个**骨架**：

```
引擎（engine/）  ——已经写好了：检索、注入、交接、落账、要目、验收、快照
宿主（host/）    ——要你自己接：什么时候写、什么时候注入
```

引擎是黑盒，跑起来就有接口；宿主是白盒，因为**每个聊天框架的消息流都不一样**，
没法替你写。

所以安装分两半：**引擎装好**（10 分钟）+ **钩子接上**（20 分钟）。

---

## 一、准备

| 需要 | 说明 |
|---|---|
| Python | 3.11 以上。只用标准库，不需要 pip install |
| 一个模型接口 | OpenAI 兼容即可（要目/交接/落账三处要用它做压缩） |
| 一个宿主 | 能收发消息、能拿到消息原文和自己发出的回复的程序 |

> 如果你的宿主根本拿不到「消息原文」，这个框架没用——它的一切都建立在原文上。

---

## 二、装引擎

### 2.1 放到一个固定位置

解压后建议放在宿主的旁边，例如：

```
<路径>\qq-bridge\
    ├─ memory-brain\        ← 把 engine/ 里的东西放这里
    │    ├─ paths.py
    │    ├─ memory_inject.py
    │    └─ ...
    ├─ state\               ← 宿主的状态目录（应该已经存在）
    └─ src\                 ← 宿主代码
```

**为什么放在宿主旁边**：默认会去 `<宿主>/state` 读社交状态，放一起最省事。

### 2.2 填路径

```bash
cd <路径>\qq-bridge\memory-brain
python configure.py
```

它会问四个问题：

```
QQ 桥接目录（例如 <路径>\qq-bridge）: <路径>\qq-bridge
状态目录（social-v2 / her-notes）: <路径>\qq-bridge\state
归档根目录（例如 <路径>\归档）:     <路径>\归档
模型 API Key:                      sk-xxxx
```

回车即用默认值。生成 `paths.json`：

```json
{
  "engine": ".",
  "bridge": "<路径>\\qq-bridge",
  "state": "<路径>\\qq-bridge\\state",
  "archive": "<路径>\\归档",
  "mnemonDb": "",
  "apiBase": "https://api.deepseek.com/v1",
  "apiKey": "sk-xxxx",
  "apiModel": "deepseek-flash"
}
```

> **`paths.json` 别提交到 git**。里面有 API key。

`configure.py` 会顺手把缺的目录建好：`QQ\`、`归档要目\`、`交接\`、`her-notes\`。

### 2.3 填薄身份（可选但强烈建议）

```bash
copy her-core.template.md <路径>\qq-bridge\state\her-core.md
```

打开它，填三处：

```markdown
## 名
**<你的名字>**

## 性
<三五行。怎么说话、遇事什么反应、什么不做。>

## 目标
<一两句。你想让它成为什么、为什么。>
```

**这一页必须你自己写。** 抄别人的「我」不是「我」——
它每轮都会贴在提示词最前面，是这套系统里唯一「不可替代」的部分。

跳过这步也能跑，只是它不知道自己是谁。

### 2.4 验收

```bash
python check.py
```

第一次跑会是这样的：

```
[1] 服务
  ✗ 3132  记忆注入
[2] 归档 <今天>
  ✗ 今天还没有归档文件
[3] 流水注入
  ✗ private:xxx 没有块文件
[4] 要目
  · <昨天>  没有原文，不需要要目

  3 项异常
```

**这是正常的**——还没有数据，服务也还没起。
看到它能正确报出「缺什么」，就说明 `paths.json` 读对了。

---

## 三、接宿主（关键的一步）

引擎自己不会动，它等宿主来调。你要接四处。

打开 `host/host-hooks.js`，里面是四个函数。按顺序接：

### 3.1 归档：每条消息都落盘

**时机**：收到消息之后、自己发出消息之后。

```javascript
// 伪代码
onMessage((key, msg) => {
  // ...你原本的处理
  archiveQQ(key, msg);     // ← 加这一行
});
```

`msg` 至少要有这些字段：

```javascript
{
  isSelf: false,        // 是不是自己发的
  sender: "昵称",        // 谁发的
  plain: "说了什么",     // 正文
  at: Date.now()        // 时间戳（毫秒）
}
```

**必须加去重**：同一条消息可能被推两次（尤其带图片的）。
`host-hooks.js` 里用了一个「同分钟同内容」的 Map 挡住，照抄即可。

### 3.2 注入：每轮开头贴上记忆

**时机**：拼提示词的时候。

```javascript
const block = memoryBrainBlock(key);   // 读 <engine>/out/<key>.txt
prompt = block + 你的原提示词;
```

这个文件由引擎生成，宿主只负责「读出来贴上」。

### 3.3 交接 + 轮换：聊久了换会话

**时机**：一个回合结束（`turn/end` 之类的事件）。

```javascript
if (单步token > 预算 || 轮数 > 上限) {
  askHandoff(key);        // ① 先让引擎生成交接摘要
  setTimeout(() => {      // ② 等 15 秒（回复可能还在 flush）
    retireSession(key);   // ③ 再换会话
  }, 15000);
}
```

**顺序不能反**：先交接、后换会话。反了就是「人走了才想起来没交接」。

那两个阈值放在宿主配置里：

```json
{
  "socialV2": {
    "contextBudgetTokens": 100000,
    "contextRotateTurns": 60
  }
}
```

### 3.4 启动引擎

```bash
python memory_inject.py
```

监听 `127.0.0.1:3132`。宿主通过 HTTP 调它：

| 接口 | 作用 |
|---|---|
| `GET /refresh?key=<会话>` | 按最新消息重算注入块（回合开始前调一次） |
| `GET /handoff?key=<会话>` | 生成交接摘要（换会话前调） |
| `GET /block?key=<会话>` | 看块内容（调试用） |
| `GET /digest?date=&force=1` | 生成某天要目 |
| `GET /dormant` | 看哪些记忆睡着了 |
| `GET /wake?id=<记忆id>` | 叫醒一条 |
| `GET /star` | 记忆星图（浏览器打开） |

> 引擎没起、超时、报错，**都不该影响宿主发消息**——
> 用 2~3 秒超时，失败就用旧块或空块，绝不能让聊天卡住。

## 四、第一次跑通

按这个顺序，每步都能验证：

### 第 1 步：造一条归档

在宿主里发一条消息。然后：

```bash
type <路径>\归档\QQ\<今天>.md
```

应该看到一行：

```
- 14:20 [private:123456] 他：测试一下
```

**看不到？** 检查 `archiveQQ` 有没有真被调用、`msg.plain` 是不是空的。

### 第 2 步：生成注入块

```bash
curl "http://127.0.0.1:3132/refresh?key=private:123456"
curl "http://127.0.0.1:3132/block?key=private:123456"
```

应该返回类似：

```json
{"ok": true, "chars": 420, "tokens": 190, "items": []}
```

块内容：

```
<!--memory-brain:start-->
【这边（QQ）刚才的几句】
- 14:20 他：测试一下
<!--memory-brain:end-->
```

### 第 3 步：让宿主读到它

发第二条消息，看提示词里有没有那段 `【这边（QQ）刚才的几句】`。

**有 → 整条链路通了。**

### 第 4 步：验交接

```bash
curl "http://127.0.0.1:3132/handoff?key=private:123456"
```

会调模型，返回 400 字四块。检查 `<路径>\归档\交接\<key>.md` 有没有生成。

### 第 5 步：验要目

```bash
python daily_digest.py <今天> --force
```

生成 `<路径>\归档\归档要目\<今天>.md`。

## 五、日常怎么用

### 每天看一眼

```bash
python check.py
```

四项全绿就是健康：

```
[1] 服务      3132 / 3100 / 3000 / 8787
[2] 归档      今天的行数、会话数、时间跨度、连续重复
[3] 流水      每个会话的块大小、有没有【这边】
[4] 要目      昨天、今天有没有生成
```

退出码 `0` 正常、`1` 有异常——可以挂到任何告警里。

### 出问题时的三件工具

```bash
python check.py                     # 哪一环断了
type <engine>\logs\inject.log        # 引擎日志
curl .../star                       # 记忆星图，看检索是否正常
```

### 改之前先存档

```bash
python snapshot.py save before-change
python snapshot.py list
python snapshot.py restore snap-xxx   # 回滚（会先自动存一份 pre-restore）
```

**改记忆系统之前，永远先存一份。** 这是唯一的后悔药。

## 六、调参：五个旋钮

| 参数 | 在哪 | 默认 | 调大 | 调小 |
|---|---|---|---|---|
| `contextBudgetTokens` | 宿主配置 | 100000 | 记得更多、更贵 | 省钱、容易断 |
| `contextRotateTurns` | 宿主配置 | 60 | 少换会话 | 更省钱、更依赖交接 |
| `streamLines` | `engine/config.json` | 6 | 现场感强 | 省 token |
| `maxChars` | 宿主配置的 memoryBrain | 900 | 注入更长 | 更短 |
| `dormantDays` | `engine/config.json` | 60 | 少睡觉 | 早睡、更省检索 |

**调参的顺序**：先动 `streamLines` 和 `maxChars`（改完立刻见效），
再动那两个轮换阈值（影响的是长跑成本）。

## 七、排错表

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `RuntimeError: paths.json 还没填好` | 没跑 configure.py | 跑一次，或手写 paths.json |
| `check.py` 报服务 ✗ | 引擎没起 | `python memory_inject.py` |
| 块文件一直是空的 | 没有真人消息，或 `social-v2.json` 路径不对 | 看 `paths.json` 的 `state` |
| 归档里发言人都是「某人」 | 宿主没传 `sender` | 在 `archiveQQ` 调用处补上 |
| 同一句话出现两遍 | 宿主推送重复 | 用 `host-hooks.js` 里的去重 Map |
| 要目生成出来是空文件 | 模型把 token 花在思考上 | 把 `max_tokens` 提到 4000，空正文重试 |
| 交接摘要只有一半 | 截断位置在句中 | 按句号/分号截（`handoff._clip`） |
| 注入块太长挤爆上下文 | `maxChars` 太大 | 降到 640，或减少 `streamLines` |
| 换会话后断片 | 交接没生效 | 查 `archived` 目录有没有交接文件、90 分钟是否过期 |

## 八、安全与边界

**① 什么不能进包 / 不能进 git**

```
paths.json              含 API key
state\social-v2.json    含会话令牌
.credentials.yaml
out\                    注入块，可重生
```

**② 什么不该进记忆库**

这套系统有一条自己定的规矩：

> 记忆库只放**关于人的事**——做过什么、在意什么、答应过什么。
> 本机路径、报错栈、配置项这类「维修记录」不进记忆库。

理由是：维修记录会稀释它对自己的记忆。
`facts.py` 的提示词里已经写死了这条，别改。

**③ 真假标注不要关**

落账时会标 `（真）/（转述）/（编）`。这看着麻烦，但它是唯一能防住
「把玩笑记成事实」的机制——而那种错最难发现。

## 九、迁移：换机器怎么办

1. 存一份快照：`python snapshot.py save move-out`
2. 新机器上按第二节装好引擎
3. 把三样东西搬过去：
   - `<archive>\`（原文 / 要目 / 交接）
   - `<state>\her-notes\`（笔记 + 自动落账）
   - `<state>\her-core.md`（薄身份）
4. `python configure.py` 重新填一次路径
5. `python check.py` 验一遍

**薄身份是最该带走的**——别的都是实现细节，这一页是「它是谁」。

---

## 十、最后

这套东西跑久了，你会遇到两个反复出现的问题：

**「它怎么不记得了」** → 先看 `check.py` 里归档和块在不在，再看交接。
九成是链路断了一环，不是模型笨。

**「它怎么记得些没用的」** → 落账抽多了。
把 `facts.py` 提示词里的「三类」收紧，或者手动清理 `auto-facts-*.md`。
